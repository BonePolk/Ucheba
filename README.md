# Task Manager

React/Vite + Mantine, FastAPI/SQLModel, SQLite. Тёмная тема, акцент `#7f49b4`.
Один frontend, один backend; интеграции остаются отдельными сервисами.

## Запуск

Скопируйте `.env.example` в `.env`, задайте `ADMIN_PASSWORD` (от 16 символов) и
постоянный `INTEGRATION_ENCRYPTION_KEY` (Fernet). Ключ можно получить командой
`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
в окружении с установленной `cryptography`.

```sh
docker compose up -d --build --remove-orphans
```

Откройте `http://localhost:8080`. При переходе с предыдущей версии `--remove-orphans`
убирает старые контейнеры `admin-backend` и `admin-frontend`. Volumes и `./data`
не удаляйте. При смене структуры сервисов одного watch недостаточно.
Для последующих изменений: `docker compose up --watch`.

## Аккаунты и данные

При первом запуске создаётся `admin` с паролем из `ADMIN_PASSWORD`. Все старые задачи,
ключи, архив, память и Telegram-сессия остаются у этого аккаунта. Пароль затем
меняется в профиле; переменная используется только для первоначального создания.
Новые пользователи регистрируются с отдельными логином и паролем от 12 символов.
Пароли хешируются Argon2; авторизация — подписанная HttpOnly/SameSite=Strict cookie
на 12 часов. При смене пароля прежние сессии становятся недействительны.
При HTTPS задайте `COOKIE_SECURE=true`.

SQLite остаётся в `./data`: `tasks.db` содержит данные первого владельца, реестр
аккаунтов и общие переключатели. Каждый следующий пользователь получает отдельный
файл `./data/users/<id>.db`. Задачи, настройки, ключи, входящие, чаты, история и память
контекста выбираются только из его базы. Межсервисные запросы содержат подписанный
идентификатор пользователя. Старые cookie владельца больше не действуют.

Ключи Gemini, Telegram, токены ботов и ключ Luna сохраняются и заменяются в
**Профиле**. Поля секретов скрыты, API возвращает только признаки наличия.
Хранение — Fernet с общим серверным ключом из `.env`. Пустое поле сохраняет прежний
секрет, кнопка удаления удаляет его. Подключение ChatGPT Codex — официальная
авторизация по device code в профиле, ключ API не требуется.

Старый `LUNA_API_KEY` из `.env` однократно импортируется с шифрованием только в профиль
`admin`, если у него ещё нет настроек Luna. После успешного переноса его можно убрать
из `.env`: дальнейшие изменения делаются в профиле. Шлюз Luna — `https://lenec.tech/v1`.
Серверный ключ шифрования не меняйте: он нужен для расшифровки сохранённых секретов.

## Разделы

- `/` — задачи и архив; создание, редактирование, восстановление, полное удаление из архива.
- `/profile` — личные настройки интеграций, ключи и смена пароля.
- `/inbox` — предложения Gemini для подтверждения, исправления или отклонения.
- `/?task=<id>` — поручение Codex, оценка Jev, ответы на вопросы о контексте.
- `/admin` — только для администратора: количество пользователей и общие переключатели
  регистрации, Telegram, Gemini, Codex, Jev, Luna, сбора сообщений и уведомлений.
  Чужие задачи и ключи здесь не отображаются.

При отключении функции её настройки, кнопки и оценки скрываются в интерфейсе.
Сохранённые данные остаются на месте. Переключатели обновляются в открытом интерфейсе
раз в 30 секунд.

Отключённые функции блокируются на сервере, фоновые анализаторы и боты учитывают
переключатели. Уже отправленный внешний запрос может завершиться; отключение не
отзывает выполненное обращение у провайдера. Основной ручной CRUD задач работает
без интеграций. Регистрацию можно отключить, существующие аккаунты сохраняются.

## Интеграции

**Telegram:** Telethon для пользовательского аккаунта (API ID/Hash, телефон, код, 2FA).
Анализируются только выбранные чаты. Автоанализ получает новые сообщения; ручной —
до 50 последних за 7 дней. Идентификаторы сообщений сохраняются для дедупликации.
Сессия зашифрована и недоступна через публичные каталоги.

**Боты:** отдельные aiogram-боты сбора сообщений и уведомлений для каждого пользователя.
Один токен нельзя подключать к нескольким аккаунтам или двум функциям.
Для сборщика добавьте бота в группы, при необходимости отключите Privacy Mode
в BotFather, затем выберите разрешённые чаты. Историю аккаунта Bot API не читает.
Для уведомлений задайте свой Telegram ID и отправьте `/start` боту. Уведомления:
близкий/просроченный дедлайн, новые предложения и готовые материалы Codex.

**Gemini:** официальный `google-genai`, структурированное извлечение задач. Уверенные
новые задачи могут создаваться автоматически. Изменения и отмены требуют подтверждения.
Неизвестные даты не выдумываются.

**Контекст → Jev:** отдельный сервис `context`, официальный Python SDK `openai`,
Responses API `gpt-6-luna`. Задачи и ответы передаются настроенному внешнему шлюзу.
Luna проверяет контекст с памятью прошлых задач пользователя. При нехватке данных
вместо балла показывает конкретные вопросы и ссылку «Ответить». Предмет и ответы
сохраняются в SQLite. Для указанного предмета выбираются последние 20 записей;
без предмета — 20 кандидатов, связь с которыми модель должна проверить или уточнить.
Предположения модели не превращаются в подтверждённые факты. В UI виден расход токенов.
Повторная проверка неизменившегося контекста не расходует квоту.

Luna работает как агент: может запросить список файлов памяти и прочитать нужный
файл перед ответом. Не более трёх обращений к модели за проверку. Результаты
автоматически сохраняются в Silo, bucket `context-memory`, по пути
`users/<id>/context/task-<task_id>.json`. Номер пользователя берётся из проверенного
межсервисного запроса, модель не может выбрать чужую папку. Ключ Luna в память
не записывается. SQLite остаётся источником задач, ответов и кэшированных оценок;
старые базы не изменяются. Старые записи не переносятся в Silo автоматически,
но последние 20 записей SQLite по-прежнему доступны модели в запросе.

Для Silo добавьте в `.env` отдельные `SILO_ACCESS_KEY` (логин от 3 символов) и
`SILO_SECRET_KEY` (длинный случайный пароль, не короче 16 символов). Те же значения
используют Silo и context. Silo доступен только внутри Compose, его порты наружу
не публикуются. Объекты сохраняются в volume `silo-data`.
После этих изменений нужны пересборка образа context и создание сервисов Silo
и context с обновлённой конфигурацией. Watch исходников сам по себе не применяет
новые переменные окружения и сетевые подключения.

Диагностика 2026-11-09: в context обращения к Luna завершались
`APITimeoutError` при TLS handshake. TCP соединялся, с хоста HTTPS работал.
Из контейнера два запроса с обычным MSS завершились таймаутом; два запроса
с MSS 1200 получили HTTP 200 на `/v1/models` без ключа. Для context добавлена
отдельная исходящая сеть `context-egress` с MTU 1200 и приоритетным шлюзом;
связь с backend и Silo остаётся через обычную сеть Compose.
Нужен Compose с поддержкой `gw_priority` (2.33.1 или новее).
TLS-сертификаты проверяются. Исправление сети после пересоздания context
и полный ответ модели с ключом пока не проверены.

После достаточного контекста локальная **Laya Multilingual (322M)** в сервисе `jev`
оценивает важность и сложность. Балл важности 0–4 отображается как 0–100, ручной
приоритет не меняется. Просроченные незавершённые задачи сортируются первыми отдельно
от ИИ-балла. Laya работает на CPU, до двух потоков, запросы последовательные;
кэш весов — volume `jev-models`. Первый запрос скачивает модель и может превысить
таймаут: дождитесь загрузки и повторите. Ориентир RAM сервиса 2–3 ГБ, не измеренный
лимит. Обогащённый контекст ограничен 2048 токенами. Качество оценок нужно проверять
на собственных задачах; уверенность модели не гарантирует правильность.

**Codex:** официальный `openai-codex` SDK, вход ChatGPT по device code, зависит от
подписки и включения device code login в безопасности ChatGPT. По одной задаче
одновременно, до пяти минут. Каждый аккаунт имеет отдельные авторизацию, рабочую
директорию и UID процесса. Linux sandbox `workspace-write`, запрет повышения прав,
сетевые shell-команды отключены, встроенный web search — cached. Нет доступа к базе,
Telegram-сессиям и ключам других интеграций. При недоступности sandbox выполнение
блокируется. Результаты — файлы и краткое описание, задача переходит «На проверку»,
но не завершается автоматически. Старые материалы владельца сохраняются.

## Структура и API

```text
backend/          единый API, авторизация, задачи, управление интеграциями и фоновые задания
frontend/         единый React-интерфейс
common/           модели, SQLite, шифрование, идентификатор пользователя, межсервисные запросы
services/         telegram, collector, notifications, gemini, context, jev, codex
nginx/            общий шлюз
```

Только Nginx публикует порт 8080. `/api/tasks`, `/api/integrations`, `/api/inbox` требуют
входа, `/api/admin` — роли администратора. `/api/auth` — вход, регистрация, выход,
профиль и смена пароля. Доступ `/<service-name>/...` проксируется через авторизованный
backend с идентификатором текущего пользователя; внутренние токены не выдаются браузеру.
Отдельных приложений или API админки больше нет.

Делайте резервную копию **всего `./data`**, `.env` и volumes `codex-home`, `codex-work`,
`jev-models`. Фоновые задачи завершаются вместе с сервисами. При сбое между отправкой
уведомления и сохранением его идентификатора возможно повторное уведомление.

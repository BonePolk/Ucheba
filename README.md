# Ucheba

Персональный менеджер задач с AI-агентами для сбора контекста, планирования нагрузки, работы с календарём и выполнения поручений.

## Возможности

- **Задачи и подзадачи**: создание, редактирование, категории, приоритеты, дедлайны, архив, учёт подтверждённого времени выполнения (`completed_work_minutes`) и вложения.
- **Контекстный разбор (Monocle)**: уточнение деталей задачи по прикреплённым файлам, личным кабинетам, веб-источникам и вопросам владельцу.
- **Интеллектуальное планирование (Ameba)**: распределение задач по приоритетам и гибким периодам с учётом календаря, нагрузки, восстановления, привычек из памяти и пожеланий.
- **Постоянный календарь и Straus**: неделя и месяц, повторяющиеся события, чётность учебных недель, рабочие окна, часовой пояс и AI-редактирование/импорт расписания.
- **Выполнение задач (Arrodes)**: изолированный coding agent на базе `openai-codex` SDK с доступом к задачам, браузеру и файлам аккаунта.
- **Личные файлы и документы (Silo)**: дерево папок, редактор UTF-8 текста, предпросмотр PDF (постранично), DOCX, XLSX/ODS/CSV/TSV и изображений, переиспользование вложений между задачами.
- **Telegram и боты**: подключение пользовательского аккаунта (Telethon), бот-сборщик входящих сообщений (`collector`) с подтверждением предложений во `/inbox`, бот уведомлений о дедлайнах и результатах (`notifications`).
- **Многопользовательский режим**: изолированные SQLite-базы (или PostgreSQL-схемы) и хранилища на пользователя, управление регистрацией и общими переключателями функций в админке.

## AI-агенты

- **Monocle** (`services/monocle`) — исследует задачи, читает вложения, личные документы и страницы сайтов через общий браузер, задаёт уточняющие вопросы владельцу, формирует Markdown-разбор и подзадачи.
- **Ameba** (`services/ameba`) — LLM-first планировщик: модель сама оценивает приоритеты, оставшийся объём, контекстные совмещения и гибкие периоды работы/отдыха по календарю, памяти и пожеланиям владельца; Python проверяет только объективные ограничения (ID задач, даты, защищённые дни и подтверждённые сроки) и защищает `completed_work_minutes` отдельным подтверждением. Не изменяет постоянный календарь Straus.
- **Straus** (`services/straus`) — изменяет постоянный календарь по текстовому поручению владельца и может импортировать расписание из личных кабинетов или файлов. Накопленные правки применяются атомарно через черновик с проверкой `revision`.
- **Arrodes** (`services/arrodes`) — выполняет инженерные и исследовательские поручения по задаче в Linux sandbox с MCP-адаптером инструментов Ucheba. Переводит задачу «На проверку», не завершает её автоматически.

Вспомогательные интеграции:
- **Browser** (`services/browser`) — изолированный Playwright Chromium с раздельными профилями пользователей, ручным перехватом управления для CAPTCHA/2FA, маскированием паролей и общей очередью браузера.
- **Telegram / Collector / Notifications** (`services/telegram`, `services/collector`, `services/notifications`) — работа с чатами, сбор сообщений во входящие и отправка напоминаний.

## Архитектура

```text
frontend/              React SPA (Vite + Tailwind CSS + Radix UI + TanStack Query)
backend/               FastAPI API, авторизация, задачи, календарь, очередь и оркестрация агентов
common/                Модели SQLModel, БД и Alembic-миграции, шифрование, RPC/HMAC, Codex harness, прогресс
services/
  monocle/             Агент сбора контекста и библиотека Silo
  ameba/               Агент планирования задач и валидатор периодов
  straus/              Агент редактирования и импорта постоянного календаря
  arrodes/             Изолированный агент выполнения (openai-codex SDK + MCP)
  browser/             Общий Playwright Chromium сервис для агентов и ручного управления
  telegram/            Telethon-клиент пользовательского аккаунта
  collector/           aiogram-бот сбора сообщений
  notifications/       aiogram-бот уведомлений
nginx/                 Единая точка входа (порт 8080): маршрутизация UI, /api и прокси к сервисам
```

## Технологии

- **Frontend**: React 19, Vite 7, Tailwind CSS v4, Radix UI, TanStack Query, Lucide, Motion, `react-markdown`, KaTeX, Day.js (JavaScript, без TypeScript).
- **Backend и common**: Python, FastAPI, SQLModel, SQLite (по умолчанию) / PostgreSQL (опционально, профиль `postgres`), Alembic, `pwdlib[argon2]`, `cryptography` (Fernet), `itsdangerous`, `httpx`.
- **AI и автоматизация**: `openai-codex` SDK + MCP stdio, OpenAI Responses API (`gpt-6-luna` по умолчанию, настраиваемые endpoint и модель), Playwright, Telethon, `aiogram`, `pypdf` / `pypdfium2` / `Pillow`, Silo (MinIO/S3-совместимое объектное хранилище).
- **Инфраструктура**: Docker Compose + Compose Watch, Nginx.

## Установка и настройка

1. Скопируйте `.env.example` в `.env`:

```sh
cp .env.example .env
```

2. Заполните обязательные переменные в `.env`:
   - `ADMIN_PASSWORD` — пароль первоначального администратора `admin` (не короче 16 символов; используется только при создании пустой базы).
   - `INTEGRATION_ENCRYPTION_KEY` — постоянный Fernet-ключ для шифрования секретов и межсервисной подписи:
     ```sh
     python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
     ```
   - `SILO_ACCESS_KEY` и `SILO_SECRET_KEY` — логин (от 3 символов) и длинный пароль (от 16 символов) для внутреннего объектного хранилища `silo`.
   - `COOKIE_SECURE` — установите `true` при работе по HTTPS (`false` для локального HTTP).
   - `LUNA_API_KEY` *(необязательно)* — одноразовый импорт API-ключа AI-шлюза в зашифрованные настройки аккаунта `admin` при первом старте.
   - `ARRODES_SANDBOX` *(необязательно)* — укажите `container`, если ядро хоста/VPS запрещает вложенный `bubblewrap` (например, Ubuntu 24.04 AppArmor userns или LXC).

3. Дополнительные настройки провайдера AI (`base_url`, API-ключ или OpenAI OAuth), моделей агентов, часового пояса, сохранённых входов ЛК и ботов Telegram задаются уже в веб-интерфейсе в разделе **Настройки** (`/profile`).

## Запуск

Первый запуск и сборка всех сервисов:

```sh
docker compose up -d --build --remove-orphans
```

После запуска интерфейс доступен по адресу `http://localhost:8080`. Только Nginx публикует порт `8080` наружу.

Режим разработки с автоматической синхронизацией исходников (Compose Watch):

```sh
docker compose up --watch
```

### Миграции и опциональный PostgreSQL

По умолчанию используется SQLite в `./data`. При инициализации `backend` автоматически применяет миграции Alembic (`common/migrations`). При необходимости их можно запустить вручную в окружении приложения:

```sh
python -m common.migrate
```

Для работы с PostgreSQL предусмотрен Compose-профиль `postgres` (`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DATABASE_URL`). Для переноса существующей SQLite-базы в пустые схемы PostgreSQL (до первого запуска `backend` с новой БД):

```sh
docker compose --profile postgres up -d postgres
docker compose run --rm --no-deps backend python -m common.import_sqlite --source /data
```

## Использование

- `/` — доска активных задач и архив, быстрый статус Ameba, фильтры и сортировка.
- `/?task=<id>` — карточка задачи: описание, подтверждённое время работы, подзадачи, вложения, Monocle и Arrodes.
- `/ameba` — план недели Ameba во всю ширину экрана: адаптивная сетка карточек гибких периодов (1 колонка на телефоне, 2–3 на широком экране) с целью, контекстной подсказкой и раскрываемым объяснением, отметка прогресса и остатка задачи, отображение реальных рисков и ввод пожеланий/корректировок внизу страницы.
- `/calendar` — постоянный календарь (неделя/месяц), настройка рабочих окон, повторяющиеся события с чётностью недель и поручения Straus.
- `/files` — личный файловый менеджер Silo и сохранённые вложения задач с предпросмотром и текстовым редактором.
- `/agents` — рабочее пространство Arrodes.
- `/inbox` — входящие предложения задач от сборщика Telegram.
- `/profile` — профиль, часовой пояс, настройки AI-подключений и агентов, общая память агентов (`AgentMemory`), сохранённые входы ЛК, история запусков и вкладка «Администрирование» для владельца (также доступна по `/admin`).

## Хранение данных

- `./data/tasks.db` — реестр пользователей, общие переключатели функций и данные первого аккаунта `admin` (`id=1`).
- `./data/users/<id>.db` — изолированные SQLite-базы остальных пользователей (задачи, настройки, календарь, зашифрованные ключи, память и история).
- Docker volumes: `silo-data` (файлы пользователей и вложения), `browser-data` (профили Playwright и зашифрованные входы ЛК), `codex-home` и `codex-work` (авторизация и рабочие области Codex/Arrodes), `postgres-data` (при использовании профиля `postgres`).

Для резервного копирования сохраняйте каталог `./data`, файл `.env` (особенно `INTEGRATION_ENCRYPTION_KEY`) и указанные Docker volumes. Не используйте `docker compose down -v`, чтобы не потерять пользовательские данные.

## Ограничения

- Активные очереди агентов, живые журналы прогресса (до 100 событий) и ожидание ответа на вопрос (`ask_user`) хранятся в оперативной памяти сервисов и не переживают перезапуск контейнеров.
- Сложные формы входа, SSO на сторонних доменах, 2FA и CAPTCHA требуют ручного вмешательства владельца через встроенный просмотр/перехват браузера.
- Arrodes требует работающей Linux-песочницы (`bubblewrap` или `ARRODES_SANDBOX=container`) и не отмечает задачу выполненной автоматически.
- Записи в `Ameba` показывают гибкие рекомендации и не заменяют постоянные события в календаре.

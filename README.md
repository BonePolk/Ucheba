# Task Manager

React/Vite + Mantine, FastAPI/SQLModel, SQLite. Тёмная тема, акцент `#7f49b4`.
Один frontend, один backend; интеграции остаются отдельными сервисами.

## Запуск

Скопируйте `.env.example` в `.env`, задайте `ADMIN_PASSWORD` (от 16 символов) и
постоянный `INTEGRATION_ENCRYPTION_KEY` (Fernet). Ключ можно получить командой
`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
в окружении с установленной `cryptography`.

```sh
docker compose up -d --build --remove-orphans
```

Откройте `http://localhost:8080`. При переходе с предыдущей версии `--remove-orphans`
убирает старые контейнеры `admin-backend` и `admin-frontend`. Volumes и `./data`
не удаляйте. При смене структуры сервисов одного watch недостаточно.
Для последующих изменений: `docker compose up --watch`.

## Аккаунты и данные

При первом запуске создаётся `admin` с паролем из `ADMIN_PASSWORD`. Все старые задачи,
ключи, архив, память и Telegram-сессия остаются у этого аккаунта. Пароль затем
меняется в профиле; переменная используется только для первоначального создания.
Новые пользователи регистрируются с отдельными логином и паролем от 12 символов.
Пароли хешируются Argon2; авторизация — подписанная HttpOnly/SameSite=Strict cookie
на 12 часов. При смене пароля прежние сессии становятся недействительны.
При HTTPS задайте `COOKIE_SECURE=true`.

SQLite остаётся в `./data`: `tasks.db` содержит данные первого владельца, реестр
аккаунтов и общие переключатели. Каждый следующий пользователь получает отдельный
файл `./data/users/<id>.db`. Задачи, настройки, ключи, входящие, чаты, история и память
контекста выбираются только из его базы. Межсервисные запросы содержат подписанный
идентификатор пользователя. Старые cookie владельца больше не действуют.

Ключи Gemini, Telegram, токены ботов и ключ Luna сохраняются и заменяются в
**Профиле**. Поля секретов скрыты, API возвращает только признаки наличия.
Хранение — Fernet с общим серверным ключом из `.env`. Пустое поле сохраняет прежний
секрет, кнопка удаления удаляет его. Подключение ChatGPT Codex — официальная
авторизация по device code в профиле, ключ API не требуется.

Старый `LUNA_API_KEY` из `.env` однократно импортируется с шифрованием только в профиль
`admin`, если у него ещё нет настроек Luna. После успешного переноса его можно убрать
из `.env`: дальнейшие изменения делаются в профиле. Шлюз Luna — `https://lenec.tech/v1`.
Серверный ключ шифрования не меняйте: он нужен для расшифровки сохранённых секретов.

## Разделы

- `/` — задачи и архив; создание, редактирование, восстановление, полное удаление из архива.
- `/profile` — личные настройки интеграций, ключи и смена пароля.
- `/inbox` — предложения Gemini для подтверждения, исправления или отклонения.
- `/?task=<id>` — поручение Codex, обновление порядка Jev, ответы на вопросы о контексте.
- `/admin` — только для администратора: количество пользователей и общие переключатели
  регистрации, Telegram, Gemini, Codex, Jev, Luna, сбора сообщений и уведомлений.
  Чужие задачи и ключи здесь не отображаются.

При отключении функции её настройки, кнопки и оценки скрываются в интерфейсе.
Сохранённые данные остаются на месте. Переключатели обновляются в открытом интерфейсе
раз в 30 секунд.

Отключённые функции блокируются на сервере, фоновые анализаторы и боты учитывают
переключатели. Уже отправленный внешний запрос может завершиться; отключение не
отзывает выполненное обращение у провайдера. Основной ручной CRUD задач работает
без интеграций. Регистрацию можно отключить, существующие аккаунты сохраняются.

## Интеграции

**Telegram:** Telethon для пользовательского аккаунта (API ID/Hash, телефон, код, 2FA).
Анализируются только выбранные чаты. Автоанализ получает новые сообщения; ручной —
до 50 последних за 7 дней. Идентификаторы сообщений сохраняются для дедупликации.
Сессия зашифрована и недоступна через публичные каталоги.

**Боты:** отдельные aiogram-боты сбора сообщений и уведомлений для каждого пользователя.
Один токен нельзя подключать к нескольким аккаунтам или двум функциям.
Для сборщика добавьте бота в группы, при необходимости отключите Privacy Mode
в BotFather, затем выберите разрешённые чаты. Историю аккаунта Bot API не читает.
Для уведомлений задайте свой Telegram ID и отправьте `/start` боту. Уведомления:
близкий/просроченный дедлайн, новые предложения и готовые материалы Codex.

**Gemini:** официальный `google-genai`, структурированное извлечение задач. Уверенные
новые задачи могут создаваться автоматически. Изменения и отмены требуют подтверждения.
Неизвестные даты не выдумываются.

**Контекст → Jev:** отдельный сервис `context`, официальный Python SDK `openai`,
Responses API `gpt-6-luna`. Задачи и ответы передаются настроенному внешнему шлюзу.
Luna проверяет контекст с памятью прошлых задач пользователя. При нехватке данных
вместо балла показывает конкретные вопросы и ссылку «Ответить». Предмет и ответы
сохраняются в SQLite. Для указанного предмета выбираются последние 20 записей;
без предмета — 20 кандидатов, связь с которыми модель должна проверить или уточнить.
Предположения модели не превращаются в подтверждённые факты. В UI виден расход токенов.
Фоновая проверка неизменившегося контекста использует кэш. Кнопка «Проверить
контекст через Luna» всегда запускает новую проверку и расходует квоту.

Luna работает как агент: может запросить список файлов памяти и прочитать нужный
файл перед ответом. Не более десяти обращений к модели и 280 секунд за проверку. Результаты
автоматически сохраняются в Silo, bucket `context-memory`, по пути
`users/<id>/context/task-<task_id>.json`. Номер пользователя берётся из проверенного
межсервисного запроса, модель не может выбрать чужую папку. Ключ Luna в память
не записывается. SQLite остаётся источником задач, ответов и кэшированных оценок;
старые базы не изменяются. Старые записи не переносятся в Silo автоматически,
но последние 20 записей SQLite по-прежнему доступны модели в запросе.

Для Silo добавьте в `.env` отдельные `SILO_ACCESS_KEY` (логин от 3 символов) и
`SILO_SECRET_KEY` (длинный случайный пароль, не короче 16 символов). Те же значения
используют Silo и context. Silo доступен только внутри Compose, его порты наружу
не публикуются. Объекты сохраняются в volume `silo-data`.
После этих изменений нужны пересборка образа context и создание сервисов Silo
и context с обновлённой конфигурацией. Watch исходников сам по себе не применяет
новые переменные окружения и сетевые подключения.

Диагностика 2026-11-09: в context обращения к Luna завершались
`APITimeoutError` при TLS handshake. TCP соединялся, с хоста HTTPS работал.
Из контейнера два запроса с обычным MSS завершились таймаутом; два запроса
с MSS 1200 получили HTTP 200 на `/v1/models` без ключа. Для context добавлена
отдельная исходящая сеть `context-egress` с MTU 1200 и приоритетным шлюзом;
связь с backend и Silo остаётся через обычную сеть Compose.
Нужен Compose с поддержкой `gw_priority` (2.33.1 или новее).
TLS-сертификаты проверяются. Исправление сети после пересоздания context
и полный ответ модели с ключом пока не проверены.

В карточке контекста можно прикрепить до пяти файлов по 10 МБ: PDF, DOCX,
текст UTF-8 (включая исходный код), PNG, JPG и WEBP. Оригиналы и извлечённый текст
сохраняются в Silo в папке пользователя, отдельно для каждой задачи. Из первых
50 страниц PDF извлекается текст, для текстовых документов — до 40 000 символов.
PDF-сканы без текстового слоя тоже принимаются. В начале проверки Luna получает
каталог вложений: имена, типы, размеры, число страниц, наличие текста и preview
до 400 символов. Полное содержимое всех вложений заранее не отправляется.
Агент сам выбирает подходящие документы через `read_file`; при чтении PDF первая
страница передаётся как изображение, остальные страницы агент может запросить
по номеру через `view_pdf_page`. Это позволяет просматривать формулы,
таблицы и схемы. Страницы рендерятся PDFium в JPEG с длинной стороной 1600 px,
сохраняются в Silo по хешу оригинала и номеру страницы и повторно используются
между проверками и задачами. Оригинальный PDF сохраняется без изменений. Изображения
отправляются в Responses API; поддержка изображений внешним шлюзом Luna должна
быть подтверждена при запуске. Добавление и удаление файлов сбрасывает старую
оценку. Изменение материалов во время оценки не должно сохранять устаревший результат.

В поле «Из сохранённых файлов» можно найти документ из другой своей задачи и
прикрепить его без повторной загрузки из ЛК. Агент имеет инструменты
`list_saved_files` (поиск по имени и извлечённому тексту), `read_file` (чтение
выбранного файла) и `reuse_file` (прикрепление к текущей задаче). Luna может читать
файлы и страницы PDF из своей сохранённой библиотеки без ручного выбора и без
обязательного прикрепления к текущей задаче. Ручное поле выбора — дополнительный
вариант для владельца. Агенту указано выбирать файлы по предмету, номеру работы,
ожидаемому результату и содержимому; если имя непонятно или preview пустой,
он может открыть документ для определения темы. Вопрос владельцу нужен, если
доступные документы действительно не позволяют различить варианты.
Один запрос библиотеки возвращает до 100 файлов. При переиспользовании оригинал
копируется в текущую задачу с проверкой содержимого на дубликаты; изображения
страниц PDF берутся из общего кэша текущего пользователя. «Убрать из задачи»
теперь отсоединяет файл, сохраняя оригинал и метаданные в библиотеке. Старые
файлы остаются доступны, их метаданные PDF дополняются при чтении.
Ссылки на прочитанные файлы отображаются в источниках, включая документы из
старых задач. Они авторизованы и читают только пользовательский префикс. Доступ к
файлам другого пользователя невозможен через эти инструменты: все пути строятся
от авторизованного пользовательского префикса Silo.

Для рендеринга PDF добавлен `pypdfium2`: требуется пересборка образа context.
Python API PDFium вызывается под общим lock, поскольку библиотека не поддерживает
одновременные обращения из разных потоков. Распознавание страниц PDF через
внешний шлюз Luna и сценарий переиспользования пока не проверены запуском.

**Браузер личных кабинетов:** в карточке контекста раскройте «Браузер личного
кабинета», добавьте HTTP- или HTTPS-адрес страницы входа, логин и пароль.
Нестандартные порты поддерживаются, например `http://ibks.spbstu.ru:3508`.
Luna сама выбирает подходящий кабинет из сохранённых ЛК текущего пользователя.
Поле «Личный кабинет для просмотра / подсказки Luna» используется для ручного
просмотра и как предпочтительный вариант; очищать или заполнять его для работы
агента необязательно. Для прекращения доступа к сохранённому ЛК используйте
«Забыть вход». Логин и пароль шифруются Fernet; API возвращает только
признак их наличия. Данные входа и браузерные профили разделены по пользователям.
Сессии браузера сохраняются в отдельном volume `browser-data`; пароль и cookie
не передаются модели и не сохраняются в памяти контекста Silo.

Агент может войти, прочитать видимый текст страницы и перейти по ссылке в пределах
выбранного сайта. Автоматический вход распознаёт обычные поля логина/пароля и
кнопки входа, включая двухшаговую форму. Универсальный вход в любой ЛК не гарантируется:
нестандартные формы, перенаправление SSO на другой домен, 2FA и CAPTCHA требуют
действия владельца. Для этого есть снимок браузера с кликами, вводом, клавишами
и прокруткой. Нажмите на поле на снимке, введите значение под снимком и нажмите
«Ввести»; затем обновите снимок. В браузере можно заранее открыть нужную лабораторную
работу и запустить новую проверку Luna.

Документы из ЛК агент скачивает через `browser_download` по номеру ссылки на
прочитанной странице. Если обычный переход открывает документ или запускает
скачивание, он также обрабатывается как файл. GET-запрос использует cookie текущего
пользователя для подходящего домена; модель их не получает. Проверяются внешние
адреса на каждом перенаправлении, размер ограничен 10 МБ. Документ проходит тот же
разбор PDF/DOCX/текста/изображений, что и ручное вложение, сохраняется в Silo в
текущей задаче и сразу передаётся Luna. Повторное скачивание одинакового содержимого
не создаёт дубликат. Общий лимит — пять вложений на задачу. В источниках даётся
ссылка на сохранённое вложение, без токенов скачивания из ЛК. Скачивания через
нестандартные JavaScript-кнопки и POST-формы пока не поддерживаются.

Luna также может искать общедоступную информацию через Google (`web_search`) и
читать найденные страницы (`web_read`). Для каждого такого действия создаётся
отдельный браузер без cookie и профилей личных кабинетов. Дополнительные ключи
поискового API не нужны. В результате оценки показываются ссылки на прочитанные
страницы. Агенту явно указано не отправлять приватный текст ЛК и секреты в поиск
и не выдавать общую информацию за условия конкретной работы. CAPTCHA, блокировка
Google или изменение разметки выдачи могут сделать поиск недоступным; агент
получает сообщение об этом. Поиск в работающем приложении пока не проверен.

У агента нет инструментов произвольного JavaScript, команд, отправки форм заданий
или изменения данных ЛК. Переходы по обычным ссылкам могут иметь побочные эффекты
у нестандартных сайтов; это не гарантированный режим read-only для произвольного ЛК.
HTTP-запросы браузера к локальным и частным адресам блокируются, WebSocket и
service workers отключены. Некоторые сайты из-за этого могут работать неполностью.
Кнопка «Забыть вход» удаляет выбранные учётные данные и очищает все браузерные сессии
текущего пользователя. Файлы задач при этом сохраняются.

Нужны пересборки `context`, `browser`, `frontend`, применение нового сервиса
`browser` и обновление Nginx (лимит загрузки 16 МБ с учётом base64). Порты browser
наружу не публикуются; запросы проходят через авторизованный backend. Браузер
запускается отдельным системным пользователем в отдельном сервисе, без доступа
к SQLite, Telegram-сессиям и ключу Luna. У него только внутренний сервисный ключ
для авторизации и шифрования собственных учётных данных. Сервис browser также
использует сеть context-egress с MTU 1200. Сборки и проверки ЛК не выполнялись.

Сервис browser использует официальный образ `mcr.microsoft.com/playwright/python:v1.64.1-noble`
с готовыми браузерами и системными зависимостями. Отдельный `playwright install`
при сборке не выполняется. Python-пакет `playwright==1.64.1` должен совпадать
с версией образа; при обновлении меняйте оба значения. Для сборки по-прежнему
нужен доступ к Microsoft Container Registry и PyPI.

Итоговый формат Luna задан JSON Schema (`strict: true`). Текст промежуточных
шагов не разбирается как итог. Для шлюза, вернувшего Markdown-обёртку, она убирается;
при ошибке итогового JSON выполняется одна попытка исправить формат. Данные,
не прошедшие проверку, не сохраняются как готовый контекст.

После достаточного контекста локальная **Laya Multilingual (322M)** в сервисе `jev`
сравнивает активные незавершённые задачи попарно: какую выполнить раньше с учётом
последствий откладывания, дедлайна и зависимостей. Каждая пара сравнивается дважды
с перестановкой вариантов A/B. При противоречии или слабом различии сохраняется
исходный порядок по ручному приоритету, дедлайну и id. Сортировка использует
обычный стабильный алгоритм Python, не полный перебор всех пар. Количество
неуверенных сравнений показывается на доске; качество модели всё ещё нужно проверять.

Баллы из 100 больше не отображаются и не рассчитываются. Ручной приоритет
не меняется. Просроченные незавершённые задачи всегда выше остальных. Задачи
без готового контекста Luna остаются видны, но не участвуют в сравнении до уточнений.
На доске по умолчанию выбран «Порядок Jev» (если функция доступна), есть кнопка
«Обновить порядок Jev» и позиции вида «1 из N». Кнопка сортирует задачи с уже
готовым контекстом; фоновый обработчик продолжает проверять до трёх новых задач
за проход. Без включённого Jev или актуального результата используется обычный
порядок по ручному приоритету и дедлайну. Архив и выполненные задачи не сравниваются.

Порядок хранится в отдельной таблице `TaskRanking` каждой пользовательской SQLite.
Таблица добавляется через create_all, существующие данные и старые поля оценок
сохраняются. Снимок всего набора задач и версий контекста проверяется перед записью
и чтением порядка; изменение задачи, контекста, архива или состава списка делает
результат неактуальным. Фоновый обработчик обновляет его и при смене часа для
учёта приближающихся сроков. Кнопка проверки модели в профиле теперь сравнивает
угрозу жизни с необязательным украшением и сообщает об ошибке, если модель не
поставила угрозу первой. Эта проверка автоматически не запускалась.

Laya работает на CPU, до двух потоков, запросы последовательные;
кэш весов — volume `jev-models`. Первый запрос скачивает модель и может превысить
таймаут: дождитесь загрузки и повторите. Ориентир RAM сервиса 2–3 ГБ, не измеренный
лимит. Контекст пары ограничен 2048 токенами. Качество сравнений нужно проверять
на собственных задачах; уверенность модели не гарантирует правильность.

**Codex:** официальный `openai-codex` SDK, вход ChatGPT по device code, зависит от
подписки и включения device code login в безопасности ChatGPT. По одной задаче
одновременно, до пяти минут. Каждый аккаунт имеет отдельные авторизацию, рабочую
директорию и UID процесса. Linux sandbox `workspace-write`, запрет повышения прав,
сетевые shell-команды отключены, встроенный web search — cached. Нет доступа к базе,
Telegram-сессиям и ключам других интеграций. При недоступности sandbox выполнение
блокируется. Результаты — файлы и краткое описание, задача переходит «На проверку»,
но не завершается автоматически. Старые материалы владельца сохраняются.

## Структура и API

```text
backend/          единый API, авторизация, задачи, управление интеграциями и фоновые задания
frontend/         единый React-интерфейс
common/           модели, SQLite, шифрование, идентификатор пользователя, межсервисные запросы
services/         telegram, collector, notifications, gemini, context, jev, codex
nginx/            общий шлюз
```

Только Nginx публикует порт 8080. `/api/tasks`, `/api/integrations`, `/api/inbox` требуют
входа, `/api/admin` — роли администратора. `/api/auth` — вход, регистрация, выход,
профиль и смена пароля. Доступ `/<service-name>/...` проксируется через авторизованный
backend с идентификатором текущего пользователя; внутренние токены не выдаются браузеру.
Отдельных приложений или API админки больше нет.

Делайте резервную копию **всего `./data`**, `.env` и volumes `codex-home`, `codex-work`,
`jev-models`. Фоновые задачи завершаются вместе с сервисами. При сбое между отправкой
уведомления и сохранением его идентификатора возможно повторное уведомление.

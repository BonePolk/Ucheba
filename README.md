# Task Manager

Минимальный персональный менеджер задач на React, Mantine, TanStack Query, FastAPI и SQLModel.

## Запуск

Нужны Docker и Docker Compose:

```sh
docker compose up -d --build
```

Откройте http://localhost:8080. Наружу опубликован только Nginx; он отдаёт frontend и проксирует `/api` на backend.

```sh
docker compose down
```

SQLite хранится в volume `task-data` и сохраняется после остановки контейнеров. Команда `docker compose down -v` удаляет также базу.

## Автоматическое обновление при разработке

Для Docker Compose 2.23+:

```sh
docker compose up --build --watch
```

Изменения `backend/main.py` и `backend/models.py` синхронизируются в контейнер, после чего backend перезапускается. Изменения зависимостей или Dockerfile пересобирают backend. Изменения frontend запускают сборку Vite и пересоздают контейнер Nginx; после завершения обновите страницу браузера. `node_modules` и `dist` исключены через `.dockerignore`.

Если контейнеры уже запущены, наблюдение можно включить отдельной командой `docker compose watch`.

## Структура

- `backend/main.py` — REST API, фильтры, сортировка и создание таблиц при запуске.
- `backend/models.py` — таблица задач и схемы валидации.
- `frontend/src/App.jsx` — список задач и фильтры.
- `frontend/src/TaskForm.jsx` — общая форма создания и редактирования.
- `frontend/src/api.js` — запросы к API.
- `frontend/nginx.conf` — раздача сборки и проксирование.
- `docker-compose.yml` — два контейнера и volume SQLite.

## API

`GET /api/tasks`, `GET /api/tasks/{id}`, `POST /api/tasks`, `PATCH /api/tasks/{id}`, `DELETE /api/tasks/{id}`.

Фильтры списка: `status=todo|in_progress|done`, `priority=low|medium|high|overdue`, `category=Название`.
Сортировка: `sort_by=deadline|priority|created_at`, `order=asc|desc`.
При сортировке по приоритету `asc` означает сначала высокий. Задачи без дедлайна всегда в конце.

Дедлайн содержит дату и время. Интерфейс показывает время в часовом поясе браузера, API принимает ISO 8601 (например, `2026-12-01T15:30:00+03:00`) и хранит время в UTC. Входное время без смещения трактуется как UTC; интерфейс отправляет время с часовым поясом.

Незавершённая задача с прошедшим дедлайном получает вычисляемый наивысший приоритет и показывается перед остальными при любой сортировке. Исходный приоритет сохраняется: он снова действует при переносе дедлайна или завершении задачи. Фильтр `priority=overdue` показывает просроченные задачи; остальные фильтры приоритета их исключают. На открытой странице отметка просрочки обновляется каждую секунду, данные списка — каждые 15 секунд.

Старые дедлайны без времени при запуске backend преобразуются в 23:59 указанной даты по UTC. Данные в volume сохраняются. Временные метки создания и обновления сохраняются автоматически в UTC.

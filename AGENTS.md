# Контекст проекта для Codex

## Правила работы

- Сохраняй KISS: не добавляй слои, зависимости и функции без прямой необходимости.
- Не переписывай рабочие части и не удаляй пользовательские данные. Изменения схемы SQLite должны сохранять старые базы.
- **Не запускай Docker и не перезапускай сервисы.** Пользователь запускает Compose и работает с `watch` самостоятельно. Сообщай, если изменение требует пересборки образа или перезапуска.
- Не запускай сборки и тесты без запроса пользователя. Не добавляй тестовую инфраструктуру.
- Секреты находятся в `.env` и пользовательских базах: не читай их ради диагностики, не выводи в терминал, ответы, логи или документацию. В API выдавай только признак наличия секрета.
- Не подключай внешние AI/Telegram интеграции без запроса. Не повторяй секреты, которые пользователь ранее присылал в чат.
- Отвечай по-русски, кратко и по существу. Не задавай уточнения, если можно безопасно принять разумное решение.

## Продукт и интерфейс

Персональный Task Manager: React + Vite + Mantine + TanStack Query; Python + FastAPI + SQLModel; SQLite. Тёмная тема, фиолетовый акцент `#7f49b4`. Код преимущественно JavaScript, без TypeScript. Не добавляй Redux, календарь, очереди или другие незаказанные возможности.

Существующие разделы интерфейса: `/` — задачи и архив; `/profile` — личные настройки, интеграции и пароль; `/inbox` — предложения задач; `/?task=<id>` — контекст, Jev и Codex; `/admin` — число пользователей и общие переключатели функций. Админка и таск-борд используют один frontend и один backend. Отдельных приложений админки нет.

## Архитектура

- `frontend/` — React-приложение; основные файлы `src/App.jsx`, `TaskBoard.jsx`, `TaskForm.jsx`, `Account.jsx`, `Admin.jsx`, `Integrations.jsx`, `Inbox.jsx`, `TaskAutomation.jsx`.
- `backend/` — API, авторизация, задачи и фоновые задания.
- `common/` — общие модели, БД, настройки, шифрование, авторизация межсервисных запросов, контекст пользователя и запуск задач для пользователей.
- `services/` — изолированные интеграционные сервисы `telegram`, `collector`, `notifications`, `gemini`, `context`, `jev`, `codex`.
- `nginx/` — единая точка входа. Только Nginx публикует порт 8080; `/api` маршрутизируется в backend, UI — в frontend, сервисные пути проксируются через backend с авторизацией.
- `docker-compose.yml` содержит сервисы и Compose Watch. Для правок исходников Watch настроен; изменения Dockerfile/requirements требуют пересборки образа. Не редактируй Compose без необходимости.

### Данные и пользователи

- Старые данные остаются в `./data/tasks.db` и принадлежат первому аккаунту `admin` (id 1). При пустой базе bootstrap создаёт его с `ADMIN_PASSWORD`.
- Другие пользователи получают отдельные SQLite-файлы `./data/users/<id>.db`. Реестр пользователей и общие переключатели функций находятся в `tasks.db`.
- Все запросы и фоновые процессы должны работать в контексте соответствующего пользователя (`common.identity`, `common.database.get_engine`, `common.runtime.for_users`). Не допускай чтения или записи чужих данных.
- Пароли хешируются Argon2; авторизация использует HttpOnly cookie `user_session`. Смена пароля инвалидирует старые сессии.
- API-ключи интеграций шифруются Fernet с ключом `INTEGRATION_ENCRYPTION_KEY`; секреты показываются только в форме ввода и никогда не возвращаются открытым текстом.
- `LUNA_API_KEY` — только одноразовый импорт в зашифрованные пользовательские настройки. Не помещай ключи обратно в frontend или логи.
- Сохраняй `./data`, `.env` и Docker volumes. Не предлагай `down -v`, очистку данных или пересоздание баз.

### Интеграции (уже существуют)

- Telegram user-account: Telethon; отдельные aiogram-боты для сбора сообщений и уведомлений.
- Gemini: структурированное извлечение задач из разрешённых переписок.
- Context: официальный OpenAI Python SDK для внешнего OpenAI-совместимого endpoint GPT-6 Luna; получает историю/память задач, должен задавать конкретные вопросы при недостатке контекста.
- Jev: локальная Laya Multilingual 322M на CPU. Работает только после контекстной оценки; ручной приоритет задачи не заменяется. Просроченные незавершённые задачи сортируются отдельно и выше остальных.
- Codex: официальный `openai-codex` SDK, авторизация ChatGPT device-code; отдельная рабочая область и системный пользователь на аккаунт. Не давать доступа к базе, Telegram-сессии или секретам. Результат не должен автоматически завершать задачу.
- Все интеграции отключаются общими переключателями админки и должны продолжать учитывать индивидуальные настройки пользователя.

Подробности экранов и пользовательского сценария поддерживаются в `README.md`; перед существенными изменениями сверяйся с реальным кодом, а не считай документацию безусловно актуальной.

## Продолжение диагностики Luna (2026-11-09)

Текущая нерешённая проблема пользователя: Luna не собирает контекст задач. Пользователь сам создал корневой `logs.txt` и постарается обновлять его перед запросами. Читай этот файл при диагностике; не перезаписывай его и не считай содержащиеся в нём ошибки обязательно актуальными после изменения кода.

В изученной версии `logs.txt` четыре обращения `context → POST /analyze` закончились `502`; также есть старый `500` на `POST /api/integrations/tasks/3/jev`. Запросы доходят до context, но причины ошибок в том снимке скрыты общим обработчиком. Точная причина отказа внешнего шлюза **не установлена**. Не утверждай, что Luna исправлена или что проблема обязательно в ключе/квоте/API.

Изменения, уже внесённые в исходники:

- `backend/routers/integrations.py`: восстановлена отсутствовавшая `provider_call`. Её вызывали API интеграций и импортировал фоновый worker. Обрабатывает HTTP-ошибки, записывает состояние интеграции через `report`.
- Добавлен авторизованный `POST /api/integrations/tasks/{task_id}/context/analyze`, вызывающий `context.prepare` независимо от включения Jev.
- `frontend/src/TaskAutomation.jsx`: добавлена кнопка «Проверить контекст через Luna». Для первого обращения не нужно заранее вводить ответы; отображаются результат проверки и ошибки.
- `services/context/main.py`: добавлены обработчики ошибок OpenAI API, подключения, таймаута и Pydantic-валидации. В интерфейс возвращаются конкретные безопасные сообщения, в логи — тип исключения и HTTP-код без ключей, тела запроса или ответа провайдера.
- `common/http.py`: для остальных неожиданных ошибок добавлена безопасная запись типа исключения и числового кода в `uvicorn.error`.

Следующий шаг диагностики: после того как пользователь применит изменения через Watch и повторит проверку Luna, прочитать обновлённый `logs.txt` и определить конкретный тип ошибки. Ответы `ready`/`needs_context` кэшируются в `backend/integrations/context.py` по снимку задачи; ранее сохранённые результаты могут возвращаться без нового запроса к модели.

В последней сессии Docker socket был недоступен (`permission denied`), а `http://localhost:8080/api/auth/me` не принимал соединение (`curl`, код 7). Это наблюдения о том окружении, а не доказательство остановки приложения на ноутбуке пользователя. Не обходи ограничения песочницы и не меняй права сокета. Ничего не запускалось и не перезапускалось.

Пользователь разрешил зарегистрировать отдельный тестовый аккаунт для диагностики, но регистрация не состоялась из-за недоступности локального API. Тестовый аккаунт не создан, cookie для него нет. При восстановлении доступа можно использовать обычный `POST /api/auth/register`; не создавай пользователя обходным редактированием SQLite. Не сохраняй пароли или сессионные cookie в этом файле.

### Обновление диагностики 2026-11-09

- После разрешённого выхода из песочницы Docker Compose logs и localhost:8080 доступны. Ничего не запускалось и не перезапускалось.
- Через обычную регистрацию создан тестовый пользователь `codex_test_b7ef4f91`, id 2. `/api/auth/me` и `/api/tasks` ответили 200. Его пароль и cookie находятся только в закрытых файлах `/tmp/ucheba-test-account.json` и `/tmp/ucheba-test-cookies`; не выводить их.
- Живые логи context показывают `APITimeoutError`. HTTPS к lenec.tech работает с хоста, TCP работает из context, но обычный TLS handshake в context зависает. Два диагностических HTTPS-запроса с MSS 1200, установленным **до подключения**, получили HTTP 200 на `/v1/models`; два обычных дали таймаут. Ключи и пользовательские данные в этих запросах не использовались.
- MSS через HTTPX transport не помог: socket options применяются после подключения. Этот вариант из кода удалён. В Compose подготовлена отдельная исходящая сеть context-egress с MTU 1200 и gw_priority 1. Реальное применение сети и авторизованный ответ модели ещё не проверены; точная причина сетевой потери пакетов не установлена.
- По запросу пользователя подготовлен Silo (`pgsty/silo:RELEASE.2026-10-26T00-00-00Z`), volume silo-data, без публикации портов. В context добавлены MinIO Python SDK и агентское чтение памяти в `context-memory/users/<id>/context/`; результаты записывает приложение. SQLite и существующие данные сохраняются.
- Пользователь должен заполнить отдельные SILO_ACCESS_KEY/SILO_SECRET_KEY в .env, пересобрать context и создать Silo/context с новой конфигурацией. Самостоятельно не запускать, не пересобирать и не перезапускать сервисы. Сборки и тесты не запускались; полный агентский сценарий не проверен.

### Файлы и браузер контекстного агента

- По запросу пользователя добавлены вложения для Luna: до пяти файлов по 10 МБ на задачу. PDF/DOCX/UTF-8 извлекаются в текст, PNG/JPG/WEBP передаются как изображения. Хранилище — папка текущего пользователя в Silo. Учитывать реальную поддержку изображений шлюзом; пока она не проверена.
- Пользователь явно выбрал **автоматический вход агентом** в ЛК. Добавлен отдельный сервис `browser` (Playwright Chromium), отдельные профили пользователей в volume `browser-data`. Данные входа вводятся в интерфейсе и хранятся в Fernet-зашифрованном файле пользователя; ключ — INTERNAL_SECRET. Пароли и cookie не передавать Luna, не выводить в API и логи. API возвращает только наличие учётных данных.
- Выбор ЛК разрешает браузерные инструменты для конкретной задачи. Агент может войти обычной формой, читать текст и переходить по ссылкам выбранного сайта. Для 2FA/CAPTCHA, SSO другого домена и нестандартных форм есть управление снимком браузера. Универсальная автоматическая авторизация в любом ЛК не подтверждена.
- Изменения вложений/выбора ЛК/ручные действия браузера сбрасывают кэш оценки. Ручная кнопка проверки Luna принудительно делает новый запрос; фоновые вызовы используют кэш. Перед сохранением результата проверяется версия контекста.
- Для итогового ответа явно задаётся JSON Schema с strict=true. SDK responses.create используется вместо автоматического parse промежуточных сообщений. После json_invalid добавлены снятие Markdown-обёртки и одна попытка исправить формат без инструментов; максимум шесть запросов/280 секунд. Не утверждать, что несоблюдение формата шлюзом исправлено, без реального ответа.
- Для применения нужны пересборки context/browser/frontend и обновление Nginx (client_max_body_size 16m). Самостоятельно сборки/тесты/перезапуски не выполнять. Выполнены только чтение кода, проверка синтаксиса Python через ast и git diff --check; полный сценарий не проверен.
